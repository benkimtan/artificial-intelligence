# Local RAG with Chroma + Ollama (Llama 3.2)

A private, fully local question-answering app over your own documents. Text is chunked and embedded into a [Chroma](https://www.trychroma.com/) vector database, and answers are generated by a local LLM served by [Ollama](https://ollama.com/). No API keys, no per-query cost, and no data leaves your machine.

Each question is answered independently (no conversation memory is held).

## How it works

```
Question -> Embed question -> Chroma similarity search (over saved embeddings)
         -> Top-k relevant chunks -> Build prompt (question + chunks)
         -> Ollama (Llama 3.2) -> Answer
```

Ingestion (chunking and embedding your documents into Chroma) is a separate, one-time offline step. At query time, Chroma simply loads the saved embeddings from disk.

## Project structure

| File | Purpose |
|------|---------|
| `rag_core.py` | Shared logic: Chroma connection, retrieval, prompt building, Ollama calls. All settings live here. |
| `rag_cli.py` | Terminal interface (single question or interactive mode). |
| `streamlit_app.py` | Streamlit web GUI with a settings sidebar. |
| `chainlit_app.py` | Chainlit chat GUI with retrieved chunks shown as side attachments. |
| `documentEmbed.py` | Embedding script for document in pdf or txt. |

Except for documentEmbed.py, the other three apps import from `rag_core.py`, so keep it in the same folder as whichever app you run.

## Prerequisites

You need three things: Anaconda, Ollama, and a Chroma database that has already been built from your documents.

### 1. Install Anaconda

1. Download the installer for your OS from <https://www.anaconda.com/download>.
2. Run the installer and follow the prompts.
3. Open **Anaconda Prompt** (Windows) or a new terminal (macOS/Linux) and verify:

```bash
conda --version
```

### 2. Create a virtual environment

Python 3.10 or newer is required (Chainlit needs it). 3.11 is a safe choice.

```bash
conda create -n rag-local python=3.11 -y
conda activate rag-local
```

Run `conda activate rag-local` every time you open a new terminal before using this project.

### 3. Install the Python libraries

```bash
pip install chromadb openai sentence-transformers streamlit chainlit
```

If you also run the ingestion script on PDF, add:

```bash
pip install pypdf
```

### 4. Install Ollama and pull the model

1. Download and install Ollama from <https://ollama.com/download>.
2. Pull the model:

```bash
ollama pull llama3.2
```

3. Make sure Ollama is running (the desktop app runs it in the background; otherwise run `ollama serve`). The apps talk to its OpenAI-compatible endpoint at `http://localhost:11434/v1`.

### 5. Build your Chroma database

The apps query an existing Chroma store, so you need to ingest your documents first using your ingestion script, "documentEmbed".py. By default the apps expect:

- DB folder: `./chroma_db`
- Collection name: `documents`
- Embedding model: `all-MiniLM-L6-v2` (via `SentenceTransformerEmbeddingFunction` as used in documentEmbed.py)

> **Important:** the embedding model used at query time must be exactly the same one used during ingestion, otherwise retrieval returns irrelevant chunks without raising an error. See documentEmbed.py

## Configuration

Edit the constants at the top of `rag_core.py`:

```python
CHROMA_DB_PATH = "./chroma_db"
COLLECTION_NAME = "documents"
EMBEDDING_MODEL = "all-MiniLM-L6-v2"

OLLAMA_BASE_URL = "http://localhost:11434/v1"
OLLAMA_MODEL = "llama3.2:latest"
OLLAMA_TEMPERATURE = 0.0
```

## Usage

Make sure the environment is active (`conda activate rag-local`) and Ollama is running.

### Command line

```bash
# Single question
python rag_cli.py "What is the termination clause?"

# Interactive mode (type 'exit' or 'quit' to leave)
python rag_cli.py

# Show the retrieved chunks before the answer
python rag_cli.py --show-chunks "your question"

# Override settings per run
python rag_cli.py --db-path ./chroma_policy_db --collection policy --model llama3.2:latest --k 6 "your question"
```

Run `python rag_cli.py --help` for all options (`--temperature`, `--base-url`, `--embedding-model`, `--no-stream`, `--system-prompt`).

### Streamlit GUI

```bash
streamlit run streamlit_app.py
```

Opens in your browser. DB path, collection, model, temperature, number of chunks (k), and system prompt can all be changed from the sidebar.

### Chainlit GUI

```bash
chainlit run chainlit_app.py -w
```

Opens in your browser (`-w` enables auto-reload while you edit). Settings are read from `rag_core.py`; the number of chunks retrieved is the `K` constant at the top of `chainlit_app.py`.

## Troubleshooting

| Problem | Likely cause and fix |
|---------|----------------------|
| `Collection [documents] does not exist` | The collection name doesn't match. The error lists available collections; set `COLLECTION_NAME` in `rag_core.py` accordingly. |
| Answers say "I don't know based on the given context" | Run with `--show-chunks` to inspect retrieval. Most often the query-side embedding model doesn't match the one used at ingestion. Also try a larger `--k` or a less strict system prompt. |
| `Error calling Ollama` / connection refused | Ollama isn't running. Start it (`ollama serve`) and confirm the model is pulled (`ollama list`). |
| Empty or near-empty ingestion from a PDF | The PDF is probably a scan with no text layer. `pypdf` can't read it; you'd need OCR first. |
| Chunks look ragged after PDF ingestion | PDFs contain hard line breaks mid-sentence. Join them before chunking: `re.sub(r"\n(?!\n)", " ", text)`. |
| Slow first run | `sentence-transformers` downloads the embedding model the first time it's used. |

## Notes on chunking

Chunk size and overlap strongly affect answer quality. Chunks that are too small lose context; chunks that are too large dilute the embedding. A modest overlap (for example 50 tokens on 500-token chunks) avoids cutting key sentences in half. Tune both against your own documents.
